# WhatsApp Restaurant Money Management Assistant

A conversational, WhatsApp-first financial assistant built for small restaurants in Kerala, India.

It replaces physical accounting notebooks and complicated POS software with an ordinary WhatsApp chat interface. Restaurant owners and staff can record daily sales, log expenses, manage supplier credit purchases & payments, upload payment screenshots (GPay, PhonePe, Paytm), send voice notes, and receive instant daily/monthly financial reports.

---

## 🌟 Key Features

1. **Simultaneous Multilingual Understanding**:
   - Zero pre-language selection.
   - Automatically understands **Malayalam Unicode script**, **Manglish** (Malayalam written in English letters), **English**, and **mixed code-switching** within the same message or audio note.
2. **Sales Management & Double-Count Prevention**:
   - Accepts daily totals and cash/UPI breakdowns without double counting (e.g. `"Today's sales 12500. Cash 7500 and UPI 5000"` records total ₹12,500 with ₹7,500 cash and ₹5,000 UPI).
   - Tracks time periods (Morning, Afternoon, Evening, Full Day).
3. **Expense Management**:
   - Automatically maps expenses to restaurant categories: Vegetables, Meat & Fish, Groceries, Gas, Electricity, Staff Wages, Rent, Maintenance, and Transportation.
4. **Supplier Credit & Payment Accounting**:
   - Manages credit purchases (`PURCHASE`) and payment settlements (`SUPPLIER_PAYMENT`).
   - Accounting safeguard: Settling an outstanding supplier balance updates the balance due without creating a duplicate operational expense in daily P&L.
5. **Screenshot-Based Transaction Extraction (Vision AI)**:
   - Accepts Google Pay, PhonePe, and Paytm receipts.
   - Detects transaction status (`SUCCESS`, `PENDING`, `FAILED`) and direction (`INCOMING` sale vs `OUTGOING` expense).
   - Safeguard: Failed or pending payments are never automatically recorded as completed transactions.
   - Detects duplicate screenshots via SHA-256 binary hash.
6. **Voice Note Processing**:
   - Securely downloads audio voice notes, transcribes Malayalam / Manglish / English speech via Whisper, and logs transactions.
7. **Deterministic Daily & Monthly Reports**:
   - All financial numbers, collections, operating surplus, and month-on-month metrics are computed deterministically by backend services (never hallucinated or generated by AI).
8. **Multi-Tenant Data Isolation**:
   - Strict business-level isolation ensuring each restaurant's financial data is private and secure.

## 🚀 Getting Started

### Prerequisites

- Node.js >= 20.0.0
- MongoDB >= 6.0
- Meta WhatsApp Cloud API credentials
- OpenAI API Key (optional for development, local rule engine handles fallback)

### 1. Installation

```bash
npm install
```

### 2. Environment Setup

Copy `.env.example` to `.env` and fill in your credentials:

```bash
cp .env.example .env
```

### 3. Running the Test Suite

Run the full automated Vitest test suite:

```bash
npm test
```

### 4. Running the Application

```bash
# Development mode with watch:
npm run dev

# Production mode:
npm start
```

### 5. Simulating WhatsApp Conversations Locally

You can test the entire conversation flow without Meta credentials:

```bash
npm run simulate
```

## 🛡️ Security & Accounting Safeguards

- **Prompt Injection Defense**: User messages are wrapped inside boundary delimiters and sanitized before LLM analysis.
- **Idempotency & Retry Deduplication**: `MessageLog` prevents duplicate transaction recording when Meta retries webhooks.
- **Image Fingerprinting**: Validates magic bytes (JPEG/PNG/WebP) and tracks SHA-256 hashes to prevent duplicate receipt uploads.
- **Non-Hallucinated Reporting**: AI only classifies intents and queries; math, totals, and balances are computed 100% deterministically in Node.js.
- **Audit Trails**: Every edit and void operation is tracked with user ID, timestamps, previous values, and reasons.

## 🔒 Production Rate Limiting & Reverse Proxy Configuration

### 1. Reverse Proxy Trust (`TRUST_PROXY`)
- **`TRUST_PROXY=false`** (default): Direct connections only; arbitrary `X-Forwarded-For` headers are ignored so clients cannot spoof their IP.
- **`TRUST_PROXY=1`**: Recommended when running behind a single reverse proxy (Nginx, Caddy, Cloudflare Tunnel, AWS ALB, Render). Express resolves the real client IP appended by the trusted proxy without treating all proxied users as one client and without trusting client-injected `X-Forwarded-For` entries.

### 2. Shared Rate-Limit Store (`RATE_LIMIT_STORE=mongo`)
- Rate limits are backed by an atomic MongoDB TTL bucket collection (`RateLimitBucket`), so multiple backend instances sharing the same MongoDB cluster enforce consistent global, auth, and mutation limits without requiring a separate Redis instance.
- In-memory rate limiting (`RATE_LIMIT_STORE=memory`) is rejected in `NODE_ENV=production` unless `RATE_LIMIT_ALLOW_IN_MEMORY_PROD=true` is explicitly set.

### 3. Rate Limit Tiers & Environment Variables
| Tier | Endpoints | Env Variables (Defaults) |
|---|---|---|
| Global API | `/api/*` | `RATE_LIMIT_API_WINDOW_MS=900000`, `RATE_LIMIT_API_MAX=300` |
| OTP Request | `POST /api/auth/request-otp` | `RATE_LIMIT_OTP_REQUEST_WINDOW_MS=900000`, `RATE_LIMIT_OTP_REQUEST_MAX=10` |
| OTP Verify | `POST /api/auth/verify-otp` | `RATE_LIMIT_OTP_VERIFY_WINDOW_MS=900000`, `RATE_LIMIT_OTP_VERIFY_MAX=15` |
| Sensitive Mutations | Sales, Expenses, Purchases, Payments, Stock Ops | `RATE_LIMIT_MUTATION_WINDOW_MS=60000`, `RATE_LIMIT_MUTATION_MAX=60` |
| WhatsApp Webhook | `POST /webhook/whatsapp` | `RATE_LIMIT_WEBHOOK_WINDOW_MS=60000`, `RATE_LIMIT_WEBHOOK_MAX=600` |

### 4. Production Deployment Checklist
- Use **MongoDB Atlas / Replica Set** (`MONGODB_URI`) — standalone MongoDB transaction fallbacks are disabled in production.
- Set a strong 32+ character `SESSION_SECRET`, `WHATSAPP_APP_SECRET`, non-default `WHATSAPP_VERIFY_TOKEN`, and explicit `CORS_ORIGIN`.
- Terminate HTTPS at the reverse proxy so `Secure` HTTP-only session cookies are transmitted safely.
